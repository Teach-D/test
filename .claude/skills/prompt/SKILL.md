# Prompt Improver

사용자의 프롬프트를 분석하고, 부족한 부분을 질문으로 보완하여 더 효과적인 프롬프트로 개선한다.

## 워크플로우

1. 사용자 프롬프트 수신
2. 6가지 기준으로 분석
3. 부족한 항목에 대해 질문 (최대 3개, 최대 3회)
4. 개선된 프롬프트 출력
5. 사용자 확인 후 해당 프롬프트로 작업 시작

## 분석 기준

프롬프트를 아래 6가지 기준으로 평가한다. 이미 명확한 항목은 건너뛴다.

| 기준 | 확인 내용 |
|---|---|
| 목적 | 달성하려는 것이 구체적인가? |
| 맥락 | 배경 정보(기술 스택, 현재 상태 등)가 충분한가? |
| 출력 형식 | 원하는 결과물 형태가 명시되어 있는가? |
| 제약 조건 | 제한사항, 규칙, 스타일이 있는가? |
| 대상/역할 | 누구를 위한 것인지, AI에 기대하는 역할이 있는가? |
| 예시 | 원하는 결과의 구체적 사례가 있는가? |

## 분석 결과 출력 형식

분석 후 아래 형식으로 결과를 보여준다:

```
**프롬프트 분석**

| 기준 | 상태 |
|---|---|
| 목적 | 명확 |
| 맥락 | 부족 — 기술 스택 정보 없음 |
| 출력 형식 | 명확 |
| 제약 조건 | 부족 — 성능 요구사항 불명확 |
| 대상/역할 | 해당 없음 |
| 예시 | 부족 |
```

## 질문 규칙

- 이미 명확한 항목은 절대 질문하지 않는다
- 한 번에 최대 3개 질문
- 총 질문 횟수 최대 3회
- 영향도가 높은 항목부터 우선 질문한다 (목적 > 맥락 > 출력 형식 > 제약 조건 > 대상 > 예시)
- 가능한 경우 선택지를 함께 제시한다

**질문 예시:**

> 1. **맥락**: 이 API는 어떤 프레임워크로 개발하나요? (예: NestJS, Express, Fastify)
> 2. **제약 조건**: 응답 시간이나 동시 접속 같은 성능 요구사항이 있나요?

## 개선된 프롬프트 출력

질문-답변이 끝나면 개선된 프롬프트를 마크다운 코드블록으로 출력한다:

````
개선된 프롬프트:

```
NestJS + TypeORM 기반으로 사용자 인증 API를 만들어줘.

요구사항:
- JWT 기반 인증 (Access Token + Refresh Token)
- 엔드포인트: 회원가입, 로그인, 토큰 갱신
- PostgreSQL 사용
- class-validator로 입력 검증

제약 조건:
- 비밀번호는 bcrypt로 해싱
- Access Token 만료: 15분, Refresh Token 만료: 7일
```
````

출력 후 반드시 확인 질문:

> 이 프롬프트로 작업을 시작할까요? 수정할 부분이 있으면 말씀해 주세요.

## 주의사항

- 프롬프트가 이미 충분히 명확하면 질문 없이 바로 "이 프롬프트는 충분히 명확합니다"라고 안내하고 작업을 시작한다
- 사용자가 확인하면 개선된 프롬프트의 내용대로 작업을 수행한다
- 원본 프롬프트의 의도를 변경하지 않는다. 부족한 부분만 보강한다
